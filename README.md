# Мессенджер v2 — общий чат между устройствами

## Что это
Эта версия подключается к Supabase и поддерживает общий чат с хранением сообщений в базе и обновлением в реальном времени. Тестовый вход использует Supabase Anonymous Auth, SMS пока не отправляются. Все участники теста видят один общий чат. Это этап проверки backend, не приватный мессенджер.

## Шаг 1. Создай проект Supabase
1. Открой https://supabase.com/dashboard и войди/создай аккаунт.
2. Создай новый проект, придумай пароль базы данных и выбери регион.
3. Дождись готовности проекта.
4. Открой SQL Editor -> New query.
5. Скопируй целиком `supabase/schema.sql`, вставь в редактор и нажми Run.
6. В Authentication -> Sign In / Providers включи Anonymous sign-ins (анонимную авторизацию).
7. В Database -> Publications найди публикацию `supabase_realtime` и включи таблицу `public.messages`. В некоторых версиях панели раздел может называться Database -> Replication / Realtime.

## Шаг 2. Вставь настройки проекта
1. В Supabase открой Project Settings -> API (или Connect).
2. Скопируй Project URL.
3. Скопируй публичный anon key / publishable key. Не используй `service_role` или secret key.
4. Открой `app.js` в редакторе текста (например, TextEdit в режиме обычного текста или VS Code).
5. Найди в начале строки:
   `const SUPABASE_URL = "PASTE_SUPABASE_PROJECT_URL_HERE";`
   `const SUPABASE_ANON_KEY = "PASTE_SUPABASE_ANON_OR_PUBLISHABLE_KEY_HERE";`
6. Вставь свои значения внутрь кавычек, сохрани файл.

Публичный anon/publishable key допустимо использовать в браузере только вместе с корректными RLS-политиками. Никогда не вставляй `service_role` или secret key в `app.js`.

## Шаг 3. Запусти
Из папки проекта:
`python3 -m http.server 8000`
Открой `http://localhost:8000`. Если сервер уже работает, останови его `Control+C` и запусти снова. Перезагрузи страницу. Введи имя и войди.

## Шаг 4. Проверь на двух устройствах
1. Открой сайт на Mac и отправь сообщение.
2. Открой сайт на другом телефоне/браузере. Для теста из одной Wi-Fi сети можно открыть `http://IP-АДРЕС-MAC:8000`; для доступа из интернета сайт нужно опубликовать по HTTPS.
3. Введи другое имя и отправь сообщение — оно должно появиться на обоих устройствах.

## Шаг 5. Публикация в интернете
Для публикации фронтенда удобно использовать GitHub Pages, Vercel или Netlify. Для GitHub Pages загрузи `index.html`, `style.css`, `app.js` и папку `supabase` в корень репозитория, затем Settings -> Pages -> Deploy from a branch -> `main` -> `/ (root)`. После публикации проверь вход, отправку и получение сообщений по HTTPS.

## Что пока не реализовано
- Личные диалоги один на один; пока общий тестовый чат.
- Проверка номера телефона через SMS.
- Приватные чаты, приглашения, блокировки и защита от спама.
- Удаление аккаунта и экспорт данных.

Когда общий чат будет проверен, следующий этап — приватные диалоги и затем подключение Phone Auth/SMS. Не используй этот общий тестовый чат для секретной переписки.


## Вход с постоянным аккаунтом

Текущая версия использует регистрацию и вход по электронной почте и паролю через Supabase Auth. Пароль не хранится в коде приложения. Для регистрации нужен пароль длиной не менее 8 символов. Если в Supabase включено подтверждение email, пользователь должен подтвердить почту перед первым входом.

Публикация: загрузите обновлённые `index.html` и `app.js` в корень GitHub-репозитория `messenger-v2` с заменой существующих файлов. `style.css` и `supabase/schema.sql` менять не требуется. В Supabase должен быть отключён Anonymous Sign-In или его можно оставить включённым — новая версия использует email/password.

Важно: это всё ещё один общий чат для всех зарегистрированных пользователей, а не личные переписки.
